# Правила для следующего Claude: лаунчер COLDZ

Подробная инструкция — `README.md` (1 подготовка ПК, 2 сборка, 3–4а адрес, настройки, новости, ник, 5 выпуск,
6 подпись Windows, 7 ошибка FiveM «LinkProtocolIPC»). Здесь — правила, грабли и порядок, чтобы не повторять ошибок.
Тема в репозитории сервера: `winter-server/docs/правила/лаунчер.md` и `ник.md`.

## Правила

- Лаунчер — оболочка над настоящим FiveM (решение Александра 28.10): FiveM не скачиваем и не раздаём, файлы FiveM и игры
  не меняем, вход и античит не обходим. Исключение с 0.5.4: в файле настроек `FiveM.app\CitizenFX.ini` лаунчер ставит
  4 строки сборки (`SavedBuildNumber`, `DefaultBuild`, `PureLevel`, `PoolSizesIncrease`) из `/info.json` сервера, ровно
  как FiveM пишет их сам при входе; остальное в файле (`IVPath`) не трогать никогда (README 7м). Обязательные строки лицензии FiveM (почта, фраза про Rockstar) не убирать.
- Новая версия игрокам — только после «да» Александра. Публикацию (push, релиз GitHub) защита сеанса может пропустить
  только по его словам в этой сессии; пересказ «да» из другой сессии для загрузки файлов в релиз не годится.
- Секретный ключ обновлений `C:\Users\Aaenl\.coldz-launcher-keys\updater.key` — никогда в git, в чат, в вывод, в копии.
  Открытый ключ в `src-tauri/tauri.conf.json → plugins.updater.pubkey` не менять никогда: установленные лаунчеры
  перестанут обновляться.
- Тексты для игроков — на 4 языках (RU основной, EN, ES, PT-BR), без длинных тире (правило Александра), по-простому.
- Новости — только для игроков, админские пункты не пишем (Александр 13.11).

## Выпуск по шагам

1. Своя ветка в отдельной папке: `git worktree add <папка> -b <ветка> main` (основную папку правит главная сессия —
   `news/news.json`). `npm install` там правит `package-lock.json` — откатить.
2. `npm test` → `npm run set-version -- X.Y.Z` → запись в `CHANGELOG.md` (первая строка = `-Notes`) → коммит «X.Y.Z: …».
3. Проверочная сборка без ключа: `$env:COLDZ_UPDATER_KEY = 'C:\nonexistent\updater.key'; npm run build`.
4. После «да»: в основной папке `git merge --ff-only <ветка>`, `npm run release -- -Notes "…"`.
5. `python scripts/verify-update.py X.Y.Z` — подпись верна открытым ключом, `latest.json` указывает на `vX.Y.Z`.
6. `git tag -a vX.Y.Z -m "…" <коммит>`, `git push origin main`, `git push origin vX.Y.Z`.
7. Релиз: `https://github.com/Poopseeque/coldz-launcher/releases/new?tag=vX.Y.Z&title=COLDZ+Launcher+X.Y.Z` в Chrome
   Александра (вход Poopseeque): описание, три файла из `release\X.Y.Z\` загрузкой файлов, «Latest», «Publish release».
8. `python scripts/verify-update.py --url` — то, что получают игроки: версия, установщик, подпись.
9. Строка в новость (`news/news.json`, 4 языка), коммит, push.

## Грабли

- «FiveM не найден» при установленном FiveM (14.11, 0.3.1 искал только ссылку `fivem://` и `%LOCALAPPDATA%\FiveM`): с 0.3.2
  поиск в `src-tauri/src/fivem.rs` (вручную, реестр, процесс, папки, ярлыки), журнал игрока
  `%APPDATA%\com.coldz.launcher\fivem-search.log`. Новый источник — в `Sources` и тест в `fivem.rs`.
- Кнопки под «Играть» должны влезать в одну строку на окне по умолчанию 1120×680, иначе вторая строка уходит под значки
  соцсетей: проверять `?fivem=0` на всех 4 языках (ES и PT — короткие подписи «Elegir FiveM.exe», «Escolher FiveM.exe»).
- FiveM требует родителя-оболочку — запуск только через `explorer.exe "fivem://connect/…"`; FiveM.exe с параметрами нельзя.
- explorer открывает ссылку зарегистрированным обработчиком fivem://. Обработчика нет или он ведёт на FiveM.exe, которого
  больше нет (FiveM переставили в другую папку), — Windows показывает «explorer.exe — Приложение не найдено» (16.11). Перед
  explorer лаунчер проверяет обработчик и чинит его на найденный FiveM.exe в HKCU (`fivem.rs` `ensure_link_handler`,
  запись в `fivem-search.log`).
- Ник FiveM снаружи не выставить (`nickOverride` в меню FiveM главнее `cl_nickname`), параметры ссылки до сервера не
  доходят — ник уходит серверу `POST /z_menu/nick` (`src-tauri/src/nick.rs`).
- Повторный запуск FiveM — ошибки «LinkProtocolIPC … master is already initialized» / «no master process»:
  `src-tauri/src/running.rs` (0.3.1) не запускает второй раз. Помощники FiveM — файлы без `.exe` (`FiveM_DumpServer`…).
- `news/news.json` = `json.dumps(indent=2, ensure_ascii=False)`; править скриптом, проверять JSON; GitHub кэширует до ~5 мин.
  С 0.5.0 после каждой правки `python scripts/sign-news.py` (подпись ключом новостей `news.key`, README 7е), иначе
  лаунчер 0.5.0+ файл не возьмёт; копии `release/site/launcher/` выложить на coldz.vip. Ключ новостей не ключ обновлений.
- Python: `-I` игнорирует `PYTHONIOENCODING` (кириллица в cp1252 падает); в heredoc `\f` в пути становится символом —
  тексты с путями писать файлом.
- Chrome в фоне не снимает скриншоты — смотреть страницу через `find`/`read_page`.
- «Не пускает сам FiveM, а не сервер» (15.11): с 0.3.3 проверка связи `src-tauri/src/netcheck.rs`, адреса и источники
  в README 7б. В текстах для игроков советовать только другую сеть (например, мобильный интернет), интернет, роутер,
  «повторите позже»: способы и программы обхода блокировок не упоминать нигде, даже намёком и ссылками на страницы,
  (с 0.4.0 резервный маршрут входа зовётся только так: «резервный маршрут входа», «вход через сервер COLDZ»; про права
  администратора и файл hosts говорим прямо, README 7г). Исключение с 18.11 ~17:10 МСК, слова Александра: «слово VPN
  можно использовать» — в карточке входа VPN назван как то, что помогает на время входа в FiveM, без названий программ
  и ссылок; на сайт, ВК и рекламу это не распространяется,
  где их советуют, ни в окне, ни в новостях, ни в README (в РФ их популяризация запрещена с 1.03.2024, реклама
  наказывается штрафом с 1.09.2025). Новый адрес Cfx.re: сначала найти его в исходниках FiveM и в строках
  установленного FiveM (`FiveM.exe`, `FiveM.app\*.dll`, `citizen\ui.zip`), потом вписать в `SERVICES`.
- 0.3.4: тексты `net_cfx` («Серверы FiveM недоступны у вашего провайдера…») и `net_server_down` («Сервер COLDZ сейчас
  недоступен…») согласованы с Александром: менять только с его слова. «Играть» не блокировать никогда: карточка
  с «Всё равно играть» / «Повторить». Проверка идёт и при запуске (тихо, строка под «Играть» только при проблеме).
- 0.3.5: резервные маршруты (`src-tauri/src/route.rs`, README 7в): список `relays` в `news.json`, вшитый — в
  `launcher.config.json`. В текстах для игроков только «основной сервер» / «резервный маршрут» (правило
  про тексты выше, 15.11). Основной сервер проверяется первым всегда; новых строк под «Играть» не добавлять
  (окно 1120×680), строка маршрута живёт в ячейке статуса.
- Снимки окна 1120×680 без кликов: headless Edge `--window-size=1120,680 --virtual-time-budget=9000 --lang=ru
  --screenshot=…` на `ui/index.html?net=blocked&card=play` через `python -m http.server` (новый профиль `--user-data-dir`).

- «Updating game storage» внутри игры и вылет через ~96 с (20.11, 0.5.4): FiveM запускать уже на сборке сервера.
  `gamebuild.rs` ставит её в `CitizenFX.ini` до запуска (README 7м), только пока FiveM не запущен. Сравнивать как FiveM
  (исходники `NetLibrary.cpp`, `XBRInit.cpp`); новый ключ сервера — сначала найти в исходниках FiveM, потом в
  `gamebuild::wanted` и тест. На этом ПК `CitizenFX.ini` владельца не трогать: тесты только на временных файлах.

## Проверка

- `npm test`: ник (правила как у сервера, ответы сервера, HTTP к поддельному серверу), процессы FiveM и закрытие
  пустышки, адреса, новости.
- Вид: `python -m http.server 8767` из корня → `http://127.0.0.1:8767/ui/index.html?fivem=0|address=0|nick=down|run=open|starting|stuck&close=fail`.
- «Указать FiveM.exe вручную» в окне: `?fivem=0&pick=ok` (нашёл) и `?fivem=0&pick=wrong` (выбран не FiveM.exe).
- Проверка связи в окне: `?net=blocked|list|offline|server|listserver`, `?netseq=blocked,ok` (ответы по очереди: запуск,
  «Играть»/«Повторить», …), `&card=play` (сам нажимает «Играть»), `&card=check` («Проверить связь»). `npm test`
  (`netcheck`): шаги на поддельных серверах (dns, connect, tls, timeout, slow после 16 КБ, медленная связь),
  `/info.json` сервера, итоги, короткие таймауты, настоящие адреса Cfx.re с этого ПК (печатает ответы; наш боевой
  сервер тесты не трогают).
- 0.5.0 (README 7д-7к): `?hint=fixup|low_disk|two_gta|onedrive|slow_disk|crash`, `&card=report|settings`,
  `?restart=12` (строка), `?restart=1&card=play` (карточка перезапуска), `?update=1`, `?portable=1&update=1`,
  `&tray=1`. Маленькие экраны: Edge `--force-device-scale-factor=1.5 --window-size=887,460` (размер в логических точках).
  Подпись новостей: после правки `news/news.json` всегда `python scripts/sign-news.py`, тест `news_signature`.
- 0.5.4: `?build=1&card=play` (строка «нажмите «Continue»»), тесты `gamebuild::tests`, `game_build_from_the_server`,
  `game_build_line_in_the_window`.


## Урок 19.11 (0.5.0 → 0.5.1): перед публикацией запускать собранный exe

0.5.0 падал у всех игроков сразу после старта, до появления окна: в `lib.rs` строка `.manage(ReadyUpdate(...))` стояла
дважды, Tauri 2.12 на повторной регистрации состояния паникует (код выхода c0000409, в журнале Windows «Application Error»,
в stderr «state for type ... is already being managed»). Тесты и `npm run build` этого не ловят.

Правило: после `npm run release` распаковать портативный zip во временную папку и запустить exe на 25 секунд с
перехватом stderr (PowerShell `Start-Process -RedirectStandardError`); публиковать только если процесс жив, окно «COLDZ»
появилось и stderr пустой. Если сломанная версия уже вышла: сначала вернуть «последнюю» на предыдущую (GitHub — PATCH
релиза `make_latest`, зеркало — положить старый `latest.json`), потом чинить и выпускать следующую.

## Урок 20.11: «лаунчер не запускается, даже процесс не создаёт»

Без WebView2 (удалён «чисткой» Windows, ключ реестра остался, установщик его не ставит; портативный zip не ставит
никогда) и при любой панике на старте release-сборка без консоли исчезала молча. С ветки `fix/start-error-message`
(`startup.rs`, README 7л) до Tauri проверяется WebView2 (окно со ссылкой Microsoft), паника пишется в `start-error.log`
и показывается окном. Перед выпуском, кроме 25-секундного запуска, проверить оба окна: `COLDZ_FAKE_NO_WEBVIEW2=1`,
`COLDZ_FAKE_START_PANIC=1`. Если на ПК уже запущен лаунчер, новая копия по single-instance сразу выходит с кодом 0:
для проверки окна «COLDZ» сначала закрыть установленный лаунчер.
