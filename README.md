# Лаунчер COLDZ

Лаунчер для игроков сервера COLDZ на Windows. Он:

- проверяет, установлен ли FiveM; если нет — ведёт на официальную страницу загрузки `https://fivem.net/` (сам FiveM не скачивает и в установщик не входит) и сам замечает, когда FiveM появился;
- по кнопке **«Играть»** запускает настоящий клиент FiveM с подключением `fivem://connect/<адрес>`; с 0.5.4 перед этим
  ставит FiveM сборку игры, которую просит сервер, чтобы FiveM качал данные сборки до игры, а не внутри неё (раздел 7м);
- при запуске (тихо), перед «Играть» и по кнопке «Проверить связь» проверяет, доходят ли до серверов FiveM (Cfx.re), и отдельно до сервера COLDZ: если провайдер режет Cfx.re, игрок видит, что дело не в COLDZ; играть это не мешает — «Всё равно играть» (раздел 7б);
- даёт поставить **ник**, который будет на сервере (поле «Ник» над «Играть», раздел 4а): менять можно когда угодно, пусто — ник из FiveM;
- показывает статус сервера: онлайн или нет, игроков из 48, пинг (обновляется каждые 20 секунд), адрес сервера с кнопкой «Копировать» (для F8 → `connect <адрес>`);
- показывает новости и правила из файла `news.json` в интернете (без интернета — последние сохранённые); оттуда же может взять адрес сервера — менять адрес можно без новой версии лаунчера (раздел 3);
- ссылки на ВКонтакте, YouTube, Discord, Facebook EN/PT, TikTok (пустые не показываются);
- выглядит как экран загрузки сервера (`z_loadscreen`): чёрный фон, тонкий COLDZ с кровью, тёмно-красные акценты, та же вводная фраза и те же правила;
- окно можно растягивать и разворачивать на весь экран, в узком окне всё встаёт в одну колонку;
- языки RU (основной), EN, ES, PT-BR — выбирается сам по языку Windows, можно переключить вверху;
- сам обновляется: при запуске проверяет новую версию на GitHub и ставит её по кнопке «Обновить».

Внизу окна лаунчера и на странице лицензии в установщике есть обязательные по лицензии FiveM (п. 2.3) строки: почта владельца и фраза
`COLDZ IS NOT APPROVED, SPONSORED, OR ENDORSED BY ROCKSTAR GAMES.`

Сделан на **Tauri 2** (Rust + встроенный в Windows браузер WebView2): установщик **~2,5 МБ**, программа после установки ~5 МБ. Память: сам лаунчер ~35 МБ, вместе со встроенным браузером Windows ~200 МБ (как одна вкладка Edge). Процессор: 0% в свёрнутом виде и пока окно не активно (например, во время игры) — анимации останавливаются.

## Что можно и чего нельзя (правила FiveM)

Лицензия FiveM (Creator PLA от 10.09.2026) отдельно про лаунчеры ничего не говорит. Официального ответа Cfx.re на этот вопрос тоже нет (вопрос на форуме от 15.09.2026 остался без ответа). Поэтому лаунчер сделан максимально безопасно:

| Можно (так и сделано) | Нельзя |
|---|---|
| Запускать **настоящий** FiveM, установленный игроком, с адресом сервера | Своя сеть / синхронизация в обход FiveM (как RAGE:MP) — закроют |
| Читать открытые адреса сервера `/info.json`, `/players.json`, `/dynamic.json` | Класть FiveM в установщик или раздавать его файлы (п. 2.2 — права распространять нет) |
| Новости, ссылки на соцсети | Менять файлы FiveM или игры, внедрять код, обходить вход или античит |
| С 0.5.4: записать в файл настроек FiveM `CitizenFX.ini` сборку игры, которую просит сервер (те же 4 строки, что FiveM пишет сам при входе на COLDZ; раздел 7м) | Трогать в `CitizenFX.ini` что-то ещё (`IVPath` и прочее), править файлы программы FiveM |
| Название и логотип COLDZ | Писать «GTA», «Rockstar», использовать их логотипы в названии и оформлении (п. 2.3) |
| Почта владельца + фраза про Rockstar на видном месте (п. 2.3) | Реклама сторонних брендов и спонсоров (п. 3.1(7)) |
| Лаунчер бесплатный и необязательный | Продавать валюту, лутбоксы и т. п. (п. 3.1) — к лаунчеру не относится, но правило общее |

Совет: лаунчер — удобство, а не обязательное условие. В Discord и описании сервера оставьте и обычный способ: FiveM → поиск «COLDZ» или ссылка `cfx.re/join/...`.

## 1. Подготовка ПК (один раз)

На ПК Александра всё уже установлено (6.11.2026). На новом ПК:

1. **Node.js 22** — https://nodejs.org/ (LTS).
2. **Microsoft C++ Build Tools** — https://visualstudio.microsoft.com/visual-cpp-build-tools/ → отметить «Разработка классических приложений на C++» (~3–4 ГБ, нужны права администратора).
3. **Rust** — https://rustup.rs/ → `rustup-init.exe`, всё по умолчанию.
4. Открыть новое окно PowerShell в папке проекта и выполнить `npm install`.

## 2. Сборка — одна команда

```powershell
npm run build
```

Первый раз ~5–10 минут (качаются библиотеки), потом ~3 минуты. Готовый установщик:

```
release\<версия>\COLDZ-Launcher_<версия>_x64-setup.exe   ← его дают игрокам
release\<версия>\COLDZ-Launcher_<версия>_x64-setup.exe.sig
release\<версия>\latest.json                            ← для автообновления
```

Установщик ставит лаунчер без прав администратора (в профиль пользователя), создаёт ярлык и сам доустанавливает WebView2, если его нет (на Windows 10/11 он почти всегда уже есть).

Проверка без установки: `npm run dev` — откроется окно лаунчера. Тесты: `npm test`.

**Проверка кнопки «Играть»** (2 минуты):

1. Полностью закрыть FiveM.
2. Запустить установщик из `release\<версия>\`, открыть лаунчер с ярлыка.
3. Должно быть: «Сервер онлайн», игроки, пинг, «FiveM установлен — можно играть».
4. Нажать «Играть» → лаунчер сворачивается, открывается FiveM и сам подключается к адресу сервера (раздел 3).

Проверка вида без сборки: открыть `ui/index.html` через любой локальный веб-сервер из корня проекта (например `python -m http.server 8767`, затем `http://localhost:8767/ui/index.html`). Без Tauri страница работает на примерных данных; `?fivem=0` — «FiveM не установлен», `?address=0` — «адрес ещё не опубликован».

Если FiveM уже открыт и вы уже на этом сервере, повторное нажатие ничего не делает — FiveM просто игнорирует команду, игра не прерывается.

## 3. Адрес сервера — где менять

Адрес задаётся в **двух местах, главное — второе**:

1. **`news/news.json` → `"serverAddress"`** (на GitHub). Если тут не пусто — лаунчер берёт адрес отсюда. **Новая версия лаунчера не нужна**: поправили файл на GitHub → у игроков новый адрес при следующем запуске лаунчера (до ~5 минут кэша GitHub). Работает в лаунчерах начиная с версии 0.2.0.
2. **`launcher.config.json` → `"serverAddress"`** — запасной адрес, вшитый в лаунчер (если нет интернета до GitHub и лаунчер ещё ни разу не скачивал новости). После правки — пересобрать и выпустить версию (раздел 5).

Сейчас **оба пустые** — заглушка: лаунчер пишет «Скоро открытие», «Адрес сервера появится здесь перед открытием», кнопка «Играть» неактивна.

**Резервные маршруты (с 0.3.5)** — `news/news.json` → `"relays"`: список `IP:порт`, по порядку (сейчас
`["177.3.198.34:30120", "46.247.40.34:30120"]`, Варшава и Алматы). Нет ключа в `news.json` — вшитый список
`"relays"` из `launcher.config.json`; пустой список `[]` — без резервных маршрутов. Как лаунчер выбирает — раздел 7в.

Формат адреса: `IP:порт` (`203.0.113.10:30120`), имя хоста (`play.example.ru:30120`, без порта — 30120) или код `cfx.re/join/abc123`. Что-то другое (пробелы, `?`, `/`, порт 0) лаунчер не примет и останется на запасном адресе. Адрес `127.0.0.1` — это ваш ПК, у игроков он работать не будет.

## 3а. Остальные настройки — файл `launcher.config.json`

```json
{
  "serverAddress": "",
  "relays": ["177.3.198.34:30120", "46.247.40.34:30120"],
  "maxPlayers": 48,
  "ownerEmail": "aaenlly@gmail.com",
  "newsUrl": "https://raw.githubusercontent.com/Poopseeque/coldz-launcher/main/news/news.json",
  "links": [
    { "icon": "vk", "label": "ВКонтакте", "url": "https://vk.ru/coldz_server" },
    { "icon": "facebook", "label": "Facebook (English)", "badge": "EN", "url": "https://www.facebook.com/..." },
    { "icon": "tiktok", "label": "TikTok", "url": "" }
  ]
}
```

- **`serverAddress`** — запасной адрес (раздел 3).
- **`relays`** — вшитые резервные маршруты (с 0.3.5, раздел 7в); список в `news.json` главнее.
- **`links`** — кнопки соцсетей внизу окна, в том же порядке. Ссылок можно сколько угодно. `icon` — значок: `vk`, `facebook`, `youtube`, `tiktok`, `discord`, `telegram`, `instagram`, `x`; `label` — подсказка при наведении; `badge` — маленькая подпись на значке (необязательно, например `EN`/`PT`); `langs` — только при этих языках окна (`ru`, `en`, `es`, `pt-BR`; нет поля — при всех; 20.11: Instagram — `coldz_gta5_dayz` для ru и es, `_en`, `_br`; TikTok — `coldz_gta5` для ru и es, `_en`, `_br`). Только ссылки `https://`.
- Ссылка с пустым `url` (`""`) просто не показывается — так сейчас с Telegram. Как появится канал — впишите `https://t.me/...`.
- После любой правки этого файла — пересобрать и выпустить новую версию: настройки вшиваются в лаунчер.

## 4. Новости, правила, адрес — файл `news/news.json`

Лаунчер берёт из `news/news.json` этого репозитория на GitHub (адрес в `newsUrl`), с 0.5.0 одновременно и с
`https://coldz.vip/launcher/news.json` (`newsUrls`), и только с верной подписью (раздел 7е):

- `"serverAddress"` — адрес сервера (раздел 3);
- `"relays"` — резервные маршруты к серверу (с 0.3.5, разделы 3 и 7в);
- `"rules"` — вкладка «Правила». Сейчас там те же 6 правил на 4 языках, что на экране загрузки сервера (`winter-server/resources/[z]/z_loadscreen/locales/*.json` → `rules`). Поменяли правила на сервере — поправьте и здесь;
- `"items"` — новости.

Чтобы опубликовать новость, ничего пересобирать не нужно. **С 0.5.0 файл подписан** (раздел 7е): правка прямо на
сайте GitHub без подписи лаунчер 0.5.0+ не примет (покажет прошлые новости), поэтому так:

1. В папке лаунчера поправить `news/news.json` (добавить запись в `items`, пример ниже).
2. `python scripts/sign-news.py`: подпись `news/news.json.sig` ключом новостей и копии для сайта в `release/site/launcher/`.
3. `npm test` (тест `news_signature` проверит подпись), коммит, push. Копии из `release/site/launcher/` выложить на
   `https://coldz.vip/launcher/` (раздел 7е).
4. Игроки увидят новость при следующем запуске лаунчера (GitHub может отдавать старую версию до ~5 минут).
   Лаунчеры 0.3.x-0.4.0 подпись не проверяют и читают только GitHub: им подходит тот же файл.

```json
{
  "id": "wipe-2026-12-01",
  "date": "2026-12-01",
  "pinned": false,
  "title": { "ru": "Вайп 1 декабря", "en": "Wipe on December 1", "es": "Wipe el 1 de diciembre", "pt-BR": "Wipe em 1º de dezembro" },
  "body":  { "ru": "Текст новости…", "en": "News text…" },
  "url": "https://discord.gg/FUMCMhdNH7",
  "image": "https://…/картинка.jpg"
}
```

- Языки можно заполнять не все: если перевода нет — покажется русский текст.
- `pinned: true` — новость всегда сверху с пометкой «Важно».
- `url` (кнопка «Подробнее») и `image` — необязательные, только `https://`.
- Если запятая или кавычка будет пропущена, лаунчер покажет прошлые новости. Проверить файл можно на https://jsonlint.com/.

Почему так, а не канал Telegram: JSON на GitHub бесплатный, стабильный и даёт тексты на 4 языках. Читать канал Telegram можно только разбором его веб-страницы — это ломается при любой смене вёрстки Telegram и не работает там, где Telegram заблокирован.

## 4а. Ник на сервере (с версии 0.3.0)

Над кнопкой «Играть» — поле **«Ник»**. Что поставил игрок, то и будет его ником на сервере везде: список игроков (Tab), F2, ник над головой, чат, таблица лидеров, подпись у трупа, клан, GPS. Менять можно когда угодно, одинаковые ники у разных игроков можно (как в DayZ). Лаунчер помнит ник. **Пустое поле — ник из FiveM.**

Правила (те же, что на сервере): русские и английские буквы, цифры, пробел, `-` и `_`, хотя бы одна буква или цифра, до 20 русских или 40 английских букв (40 байт). Нельзя слова команды в любом написании — админ/admin, модер/moderator, создатель/creator, owner, владелец, поддержка/support, helper, staff, developer, разработчик; весь ник «Server», «Сервер», «System», «Console», «COLDZ» (включая «Аdmin» с русской «А», «Adm1n», «A d m i n»). Метку роли (Создатель, Администратор, Модератор) рисует только сервер — ником её не подделать. Список слов — на сервере: `winter-server/resources/[z]/z_menu/config.lua` → `nick`.

Что видит игрок после «Играть»:

- ник не по правилам — красная подсказка под полем сразу при вводе, «Играть» неактивна;
- сервер отказал (слова команды, слишком часто) — причина под полем, FiveM **не** запускается;
- всё хорошо — «Ник „…“ будет на сервере при входе», запускается FiveM; в игре после появления — «Ваш ник на сервере: …»;
- сервер не ответил (нет связи, старый сервер без поддержки ника) — «ник не поменяли», FiveM запускается как обычно.

Как устроено (почему не через сам FiveM): ник самого FiveM нельзя надёжно выставить снаружи — поле «Ник» в меню FiveM хранится во встроенном браузере FiveM и всегда главнее настройки `cl_nickname` в `%APPDATA%\CitizenFX\fivem.cfg`; параметры ссылки `fivem://connect/…?…` до сервера не доходят (FiveM читает из них только `streamerMode`); запускать FiveM.exe с параметрами FiveM не даёт. Поэтому лаунчер сообщает ник **нашему серверу** перед запуском FiveM:

```
POST http://<адрес сервера>/z_menu/nick      {"nick": "Снег", "launcher": "<случайный номер этой установки>"}
→ {"ok": true, "nick": "Снег"}   или   {"ok": false, "reason": "reserved" | "chars" | "long" | "often" | "bad"}
```

Это тот же адрес и порт, что `/dynamic.json` (ресурс `z_menu`, файл `server/nick.lua`). Сервер помнит ник 10 минут по IP игрока; игрок с этого IP подключился — ник его; при «Играть» в главном меню сервера персонаж переименовывается. Перезашёл без лаунчера (вылет, «Переподключиться» в FiveM) — ник тот же; сменил ник в самом FiveM — ник из FiveM. Если с одного IP (одна квартира) почти одновременно пришли ники из двух лаунчеров — сервер не гадает, ник не меняет и пишет об этом в игре. Лаунчер хранит ник и случайный номер установки в `%APPDATA%\com.coldz.launcher\settings.json`.

Если игрок уже в игре, «Играть» FiveM не прерывает (раздел 2) — новый ник будет при следующем входе.

Проверка вида без сборки (раздел 2): `?nick=down` — сервер «не отвечает»; ник со словом admin/админ — «нельзя», со словом often — «слишком часто».

## 5. Выпуск новой версии (автообновление)

Один раз: на GitHub (аккаунт `Poopseeque`) создать **публичный** репозиторий `coldz-launcher` и отправить туда этот проект (`git remote add origin https://github.com/Poopseeque/coldz-launcher.git`, `git push -u origin main`). Публичный — потому что игроки скачивают из него установщик, обновления и новости. Секретов в проекте нет: ключи лежат вне папки.

Каждый выпуск:

```powershell
npm run set-version -- 0.1.1
npm run release -- -Notes "Новый адрес сервера"
git add package.json src-tauri/Cargo.toml src-tauri/Cargo.lock src-tauri/tauri.conf.json
git commit -m "Версия 0.1.1"; git push
```

`npm run release` подписывает обновление ключом из `C:\Users\Aaenl\.coldz-launcher-keys\updater.key` (сам находит его; без ключа выпуск остановится с ошибкой) и кладёт `.sig` и `latest.json` рядом с установщиком.

Что нового — запись в `CHANGELOG.md` в том же коммите, что и версия (с 0.3.4); её первая строка — текст для `-Notes`.

Проверка подписи открытым ключом (секретный не нужен): `python scripts/verify-update.py 0.1.1` — файлы `release\0.1.1\`; после публикации `python scripts/verify-update.py --url` — то, что получают игроки. Порядок выпуска и грабли для Claude — `docs/ПРАВИЛА.md`.

Затем на GitHub: **Releases → Draft a new release** → тег `v0.1.1` → прикрепить три файла из `release\0.1.1\` (`…setup.exe`, `…setup.exe.sig`, `latest.json`) → **Publish release**.

Все установленные лаунчеры при следующем запуске покажут «Вышла новая версия лаунчера 0.1.1 — Обновить».
С 0.5.0 лаунчер сразу после проверки скачивает обновление в фоне (подпись проверяется при установке) и пишет
«Вышла версия X. Она уже скачана и поставится сама, когда вы закроете лаунчер.»: по «Обновить» ставится сразу (лаунчер
перезапускается), а при закрытии окна ставится тихо, без вопросов (установщик в режиме passive: только полоска), и
лаунчер заново не открывается (`lib.rs install_on_exit`, после уборки строк hosts резервного маршрута входа). Сам
`.exe` без перезапуска заменить нельзя: Windows держит запущенный файл. Предпросмотр: `?update=1`. Ссылка для скачивания на сайт/в Discord всегда одна и та же:
`https://github.com/Poopseeque/coldz-launcher/releases/latest`

### Ключ обновлений — важно

Обновления подписаны своим ключом (бесплатно, не путать с подписью Windows). Ключ лежит **вне репозитория**:
`C:\Users\Aaenl\.coldz-launcher-keys\updater.key` (+ `updater.key.pub`).

## 6. Подпись установщика (сертификат Windows)

Сейчас установщик **не подписан** сертификатом Windows: при первом запуске Windows SmartScreen покажет «Неизвестный издатель» → игроку нужно нажать «Подробнее» → «Выполнить в любом случае». Обновления при этом защищены своим ключом (раздел 5).

Чтобы убрать предупреждение, нужен платный сертификат подписи кода (цены на ноябрь 2026, примерные — проверить перед покупкой):

- **Azure Artifact Signing** (бывший Trusted Signing, Microsoft) — **$9,99 в месяц** (~$120 в год), до 5000 подписей. Частным лицам выдают только в США и Канаде (организациям — ещё ЕС и Великобритания); нужна проверка личности по документам США. **Рекомендуемый вариант**, если владелец живёт в США. Подпись — через `COLDZ_SIGN_COMMAND`.
- **SSL.com** (сертификат на частное лицо, IV/OV) — от ~$65–130 в год у реселлеров, плюс токен или облачная подпись eSigner.
- **Sectigo / Comodo OV** — ~$220 в год; **DigiCert OV** — ~$400–440 в год.
- **SignPath Foundation** — бесплатно для проектов с открытым кодом (репозиторий уже публичный), но нужна открытая лицензия и одобрение заявки.

С 1 марта 2026 сертификаты выдают максимум на 460 дней — продлевать каждый год.

Даже с сертификатом SmartScreen какое-то время предупреждает, пока у файла не наберётся «репутация» (число скачиваний).

Когда сертификат будет — задать одну переменную окружения и собрать как обычно, скрипт подпишет и лаунчер, и установщик:

```powershell
# или: $env:COLDZ_SIGN_PFX = "C:\путь\cert.pfx"; $env:COLDZ_SIGN_PFX_PASSWORD = "..."
# или: $env:COLDZ_SIGN_COMMAND = "<своя команда подписи> {file}"
npm run release -- -Notes "..."
```

## 7. Ошибка FiveM «Failed to initialize LinkProtocolIPC» (с версии 0.3.1)

**Что это.** Окно FiveM «Failed to initialize LinkProtocolIPC, master is already initialized» (кнопки «Save information» / «Закрыть») значит: FiveM запустили второй раз, пока в памяти Windows ещё жив прошлый FiveM — завис в фоне без окна, ещё закрывается или висит с окном ошибки. Так устроен FiveM (исходники citizenfx/fivem, `LinkProtocolIPC.cpp`, `ConnectToNative.cpp`): каждый новый FiveM ищет уже работающий и передаёт ему ссылку `fivem://connect`; новая игра стартует, только если старой нет, а если в памяти осталась «живая» старая — эта ошибка. Если нажать «Играть» ещё раз, пока FiveM только запускается, бывает похожая ошибка «… no master process».

**Что делает лаунчер с 0.3.1** перед «Играть» (`src-tauri/src/running.rs`):

- FiveM не запущен — запускает, как раньше;
- FiveM открыт (окно игры или меню FiveM есть) — передаёт ему ссылку, FiveM сам подключится к COLDZ («FiveM уже открыт: подключаем…»);
- лаунчер сам запустил FiveM меньше 2,5 минуты назад, а окна игры ещё нет — второй раз не запускает: «FiveM ещё запускается, подождите»;
- процессы FiveM есть, а окна игры нет (завис, обновляется, окно ошибки) — не запускает и показывает кнопку **«Закрыть FiveM»**: закрывает все процессы `FiveM*`. Если FiveM запущен от администратора, лаунчер закрыть его не сможет и скажет закрыть через Диспетчер задач.

**Что делать игроку сейчас** (любая версия лаунчера):

1. Нажать «Закрыть» в окне ошибки.
2. Открыть Диспетчер задач: `Ctrl+Shift+Esc` → вкладка «Процессы» → снять задачу у **всех** строк, которые начинаются с «FiveM» (`FiveM`, `FiveM_b3258_GTAProcess`, `FiveM_ChromeBrowser`, `FiveM_DumpServer`, `FiveM_ROSLauncher`, `FiveM_ROSService` и т. п.). Строк может не быть на первой вкладке — тогда на вкладке «Подробности».
3. Нажать «Играть» в лаунчере **один раз** и подождать: FiveM открывается до минуты, при первом входе дольше. Повторно «Играть» не нажимать.
4. Не помогло — перезагрузить ПК (это тоже закроет всё, что осталось от FiveM).

## 7а. «FiveM не найден», хотя FiveM стоит (с версии 0.3.2)

## 7б. «Не пускает не сервер, а сам FiveM»: проверка связи с Cfx.re (с версии 0.3.3, тексты и запуск — 0.3.4)

**Что было.** 15.11 игрок: FiveM не запускается, «не пускает не сервак, а сам файв». С 2025 года часть
провайдеров РФ режет доступ к зарубежным сервисам: с 9.06.2025 к сайтам на Cloudflare проходят только первые 16 КБ,
дальше соединение висит (Ростелеком, МегаФон, Билайн, МТС, МГТС; так же Hetzner, DigitalOcean, OVH:
https://blog.cloudflare.com/russian-internet-users-are-unable-to-access-the-open-internet/). FiveM при каждом запуске

**Что делает лаунчер с 0.3.3** (`src-tauri/src/netcheck.rs`): при «Играть» (одновременно с отправкой ника) и по кнопке

один раз при запуске лаунчера, тихо (после `news.json`, где адрес сервера): около секунды и ~70 КБ, видно только
проблему; «Играть» в течение минуты после хорошего ответа не ждёт новой проверки. Все адреса сразу, обычно меньше
секунды; с 0.3.4 не дольше 5 секунд на адрес (было 8), в худшем случае ~7 секунд вместе с быстрым повтором.

**Что видит игрок (с 0.3.4).** «Играть» не блокируется никогда: проверка может ошибаться, решает игрок.

- всё отвечает: FiveM запускается как раньше;
- не отвечает обновление, вход или подключение к серверам, а сервер COLDZ (или GitHub) отвечает: при запуске лаунчера

  другую сеть (например, мобильный интернет) или повторите позже.» и ссылки «Повторить» и «Подробнее» (карточка со
  списком; ссылки, а не кнопки, чтобы вместе с плашкой обновления всё влезало в окно 1120×680). По «Играть» —
  карточка с тем же текстом, списком с отметками и кнопками **«Всё равно играть»**, **«Повторить»**, «Закрыть»;

  COLDZ сейчас недоступен: возможно, идёт перезапуск. Попробуйте через пару минут.» и те же кнопки. При запуске
  лаунчера отдельной строки нет: строка статуса уже пишет «Сервер офлайн»;
- ничего не отвечает, ни Cfx.re, ни COLDZ, ни GitHub: «Нет связи с интернетом…» и «Что можно сделать: проверить
  интернет, перезапустить роутер, попробовать другую сеть. Потом нажмите «Повторить».» (строка при запуске и карточка);
- не отвечают только список серверов или сервисы Cfx.re: «Играть» запускает FiveM (для прямого подключения они не
  нужны); «Проверить связь»: «Часть серверов FiveM недоступна у вашего провайдера, но войти на COLDZ через лаунчер это не
  мешает.»

Тексты на 4 языках (RU, EN, ES, PT-BR): `ui/i18n.js`, ключи `net_*`, `svc_*`, `play_anyway`. `net_cfx` и
`net_server_down` согласованы с Александром 15.11 (длинное тире заменено двоеточием по его правилу): менять только
с его слова.

**Нельзя:** советовать или называть любые способы и программы обхода блокировок, даже намёком (и ссылками на страницы,
где их советуют). В РФ их популяризация запрещена с 1 марта 2024, реклама наказывается штрафом с 1 сентября 2025.
Только другая сеть (например, мобильный интернет), интернет, роутер, «повторите позже». Это касается окна, новостей
и README.

**Что уходит наружу.** Ничего об игроке: обычные GET/HEAD без cookies и номеров, тот же User-Agent
`COLDZ-Launcher/<версия>`, что у новостей и статуса. Ответы не хранятся, никуда не отправляются (телеметрии нет).

**Журнал для поддержки:** `%APPDATA%\com.coldz.launcher\net-check.log` (рядом с `settings.json`): итог проверки и по
строке на адрес (где оборвалось, HTTP-код, сколько байт, сколько мс). Игрок пишет «не запускается»: попросить этот файл.

**«Пульс» входа Cfx.re (проверено 18.11.2026, 0.5.0): не добавлен.** В исходниках `code/client/shared/CnlEndpoint.h`
есть `CNL_HB_ENDPOINT "https://cnl-hb-live.fivem.net/"`, но это только значение по умолчанию: настоящая сборка берёт
адрес из переменной сборки `CFX_CNL_HB_ENDPOINT` (`code/premake5_defines.lua`), а код, который шлёт «пульс», в
открытых исходниках не лежит (заголовок подключён только в `glue/ConnectToNative.cpp`). Имени `cnl-hb` нет ни в одном
файле установленного FiveM (`FiveM.exe`, `FiveM.app\*.dll`, строки ASCII и UTF-16), а `cnl-hb-live.fivem.net` публично
не существует (NXDOMAIN у 8.8.8.8). Проверять несуществующее имя нельзя: оно всегда «не отвечает». Из `legitimacy.dll`
видно, что вход и проверка лицензии идут на `lambda.fivem.net/api/validate/...`, его лаунчер уже проверяет (`auth`).
Если Cfx.re опубликует адрес или он появится в строках FiveM: добавить в `SERVICES` и в группу `cfx` у `signin`.

Если Cfx.re поменяет адреса: список `SERVICES` в `netcheck.rs`, сверять с исходниками FiveM и строками в установленном
FiveM, тест `services_are_the_known_hosts`. Проверка вида без сборки (раздел 2): `?net=blocked` (Cfx.re режется,
COLDZ отвечает), `?net=list` (только список серверов), `?net=offline`, `?net=server`, `?net=listserver` (список серверов
и сервер COLDZ); `?netseq=blocked,ok` — ответы проверок по очереди (запуск, «Играть» или «Повторить», …), последний
повторяется; `&card=play` сам нажимает «Играть», `&card=check` нажимает «Проверить связь».

## 7в. Резервные маршруты к серверу (с версии 0.3.5)

**Зачем.** У части игроков основной адрес сервера (`serverAddress`) может не отвечать, а резервный маршрут к тому же
серверу отвечает. Решение Александра 16.11: лаунчер сам выбирает рабочий маршрут.

**Что делает лаунчер** (`src-tauri/src/route.rs`): по «Играть» спрашивает основной сервер и все резервные маршруты
сразу (`GET http://<адрес>/info.json`, ждёт ответ 200 с JSON-объектом не дольше 3 секунд). Основной ответил —
подключение напрямую, резервные не ждёт. Не ответил — первый по порядку резервный маршрут, который ответил; тот, что
сработал в прошлый раз (`settings.json` → `lastRoute`), среди резервных идёт первым. Не ответил никто — как раньше,
на основной адрес (карточка «Сервер COLDZ сейчас недоступен» с «Всё равно играть»). Ник (`POST /z_menu/nick`), статус,
пинг и адрес для F8 идут по выбранному маршруту. «Проверить связь» (и тихая проверка при запуске) спрашивает все
маршруты, показывает строку «Резервный маршрут: работает / не отвечает» и тоже выбирает маршрут; основной не отвечает,
а резервный работает — это не «сервер недоступен».

Под «Сервер онлайн» строка «Подключение: основной сервер» или «Подключение: резервный маршрут». Тексты нейтральные
(правило про тексты: docs/ПРАВИЛА.md).

**Менять маршруты:** `"relays"` в `news/news.json` на GitHub (новая версия не нужна). Резервный маршрут должен
пересылать на сервер и HTTP, и игровой трафик порта (TCP и UDP): лаунчер проверяет его по `/info.json`.

**Журнал:** в `net-check.log` в строке итога: «резервный маршрут работает / не отвечает», ««Играть»: основной сервер /
резервный маршрут». Проверка без сборки: `?route=reserve`, `?route=reserve&card=check`, `?route=none&net=server&card=play`.
Тест с настоящими маршрутами (основной адрес — недоступный `10.255.255.1:1`, ждём Варшаву):
`cargo test --manifest-path src-tauri/Cargo.toml real_routes -- --ignored --nocapture`.

## 7г. Вход в FiveM из России без VPN: резервный маршрут входа (с версии 0.4.0)

**Что было.** 18.11 Александр: «вход в FiveM из России без VPN — первостепенная задача». Игрокам из РФ приходилось:
включить VPN → запустить FiveM и войти → выключить VPN → F8 connect. Новичкам это не объяснить.

**Что режут на самом деле (измерено 18.11.2026).** Не Cfx.re: адреса из раздела 7б (`cfx-content.akamaized.net`,
`lambda.fivem.net`, `policy-live.fivem.net`) с российских узлов отвечают (HTTP 200/404 с адресов Akamai, узлы
check-host.net Москва ×2, Петербург). Режут **вход Rockstar**, который FiveM делает при каждом запуске:
`scui.rockstargames.com` (страница входа, которую FiveM показывает в своём окне), `rgl-prod.ros.rockstargames.com`,
`prod.ros.rockstargames.com` (службы Rockstar за ней), `signin.rockstargames.com`, `socialclub.rockstargames.com`.
С января 2026 эти имена стоят в списках программ обхода DPI (zapret, «Обход для Rockstar Games Launcher», сообщения
от абонентов МТС и других: «работает только с VPN»); игрок видит «Failed to connect to authentication services».
Дата-центровые узлы в Москве эти хосты видят, значит, фильтруют домашние провайдеры, а не Rockstar.
Точных замеров с домашних провайдеров пока нет: их даст сама проверка связи (ниже) по журналам игроков.

**Что делает лаунчер** (`src-tauri/src/signin.rs`, `tunnel.rs`, `hosts.rs`):

1. «Проверить связь», проверка при запуске и перед «Играть» спрашивают и адреса входа (группы `signin.groups` из
   `news.json`: сейчас «rockstar» и «cfx»), напрямую, и первый отвечающий релей COLDZ через туннель
   (`signin.tunnels`). Релей считается рабочим, только если через него прошёл манифест сборки FiveM
   (`cfx-content.akamaized.net`, не меньше 32 КБ из 64): с ноября 2026 часть провайдеров «замораживает» соединения к
   зарубежным сетям после пары десятков пакетов, и релей, который отвечает одной маленькой страницей, может быть
   бесполезен. В журнале у маршрута пишутся байты. В окне две новые строки: «Вход в FiveM (Rockstar): есть связь / нет связи» и «Резервный
   маршрут входа: работает / не отвечает / включён».
2. Вход не отвечает, а релей отвечает: текст «Вход в FiveM (Rockstar) недоступен у вашего провайдера, поэтому FiveM
   не запускается. Лаунчер может провести вход через резервный маршрут COLDZ.» и кнопка **«Включить резервный маршрут
   входа»**, под ней одной строкой: нужны права администратора, лаунчер добавит адреса в файл hosts и уберёт их сам.
   По «Играть» в этом состоянии — та же карточка (как для Cfx.re в 7б), «Всё равно играть» остаётся.
3. По кнопке лаунчер:
   * слушает `127.0.0.1:443` (занято — `127.88.0.1:443`) и каждое пришедшее соединение передаёт байт в байт
     релею внутри одного шифрованного соединения; сертификат релея самоподписанный и **закреплён** по SHA-256 из
     `news.json`, другому серверу лаунчер ничего не отдаст; имени назначения снаружи нет (релей по IP, без SNI).
     Внутри идёт собственный TLS-хендшейк FiveM с настоящим именем хоста; релей читает имя без расшифровки (nginx
     `ssl_preread`), сверяет с коротким списком (Rockstar, Cfx.re) и соединяет с настоящим хостом на 443.
     Шифрование FiveM ↔ Rockstar сквозное, ни лаунчер, ни релей внутрь не смотрят. Лаунчер пересылает только
     соединения, в хендшейке которых стоит одно из имён, что он сам записал в hosts (`tunnel.rs sni_of`);
   * записывает адреса входа в `C:\Windows\System32\drivers\etc\hosts` между двумя строками-метками
     (`# COLDZ Launcher: begin …` / `# COLDZ Launcher: end`), указывая на свой адрес. Для этого запускает сам себя
     ещё раз с `--coldz-hosts <файл>` через запрос Windows «от имени администратора» (`hosts.rs`): игрок видит один
     запрос. Повышенная копия пишет только строки вида `<127.x.x.x> <имя>` между метками (каждая строка проверяется,
     `signin.rs valid_block_line`), сбрасывает кэш DNS и выходит; других файлов не трогает;
   * записывает только группы, чья прямая проверка не прошла (`hosts_to_route`); если данных о проверке нет —
     все группы.
4. «Выключить резервный маршрут входа» и закрытие лаунчера убирают блок из hosts (ещё один запрос Windows) и
   останавливают пересылку. Игрок на запрос ответил «Нет» — блок и пересылка остаются, лаунчер так и пишет.
   При запуске лаунчер смотрит, не остался ли блок с прошлого раза (вылет): при `signin_route = "on"` в
   `settings.json` и отвечающем релее берёт его в работу без запроса (тот же адрес 127.x), иначе убирает (запрос).
5. Журнал: те же записи в `net-check.log` («вход rockstar scui.rockstargames.com: connect, … мс», «резервный маршрут
   входа включён: 12 хостов → 127.0.0.1»). С 0.5.0 по строке на **каждый** релей: номер в `signin.tunnels`, адрес,
   причина остановки, HTTP-код, сколько байт манифеста прошло и за сколько мс, у выбранного «; выбран»:
   «резервный маршрут входа, релей №1 177.3.198.34:8443: timeout (HTTP 403), 18432 байт, 8001 мс». Причины
   (`tunnel.rs Trace::stop`): `relay` (нет TLS до релея или чужой сертификат), `host_tls` (настоящий хост не ответил
   через релей), `read`/`write` (соединение оборвалось), `http`, `manifest` (нет манифеста в ответе обновлений),
   `timeout` (время вышло; байты до этого момента записаны: так видно «заморозку»), `slow` (манифест кончился раньше
   32 КБ). Пока маршрут включён, при каждой проверке и при выключении пишется работа пересылки: «работа маршрута через
   …: соединений N, отправлено/получено … байт; не пропущено: not ours 2, relay 1; последнее: <хост>, …».

**Настройка без нового выпуска:** `news.json` → `"signin"`: `groups[]` (`id`, `check` — https-адреса для проверки,
`hosts` — имена для hosts) и `tunnels[]` (`address` — `ip:порт`, `sha256` — отпечаток сертификата релея). Вшитый
запасной список — `launcher.config.json`. Пустой `tunnels` = кнопки нет, строки проверки входа есть. Лишние и кривые
записи отбрасываются (`signin.rs clean`: до 40 имён, до 8 релеев, только строчные имена с точкой).

**Релей:** `relay/tunnel/` (`tunnel.stream.conf`, `install_tunnel.sh`, `README.md`): порт 8443 на Варшаве и Алматы
в уже стоящем `coldz-relay-nginx`; скрипт печатает строку для `news.json`. Живые релеи правит только Александр или
главная с его слова.

**Риски и что решает Александр (см. CHANGELOG 0.4.0):**
- запрос Windows показывает «Неизвестный издатель» (установщик без подписи кода); с сертификатом подписи
  (Azure Trusted Signing, ~10 $/мес) запрос станет обычным. Антивирусы (Kaspersky, Dr.Web) могут спросить про правку
  hosts: игрок увидит имя лаунчера;
- пока блок в hosts, адреса входа Rockstar у всех программ на ПК идут через лаунчер, поэтому он убирает блок при выходе;
- если режут не по IP, а по имени в хендшейке, прямой проброс не помог бы; поэтому внешнее соединение к релею без
  имени, а имя спрятано внутри;
- правила Cfx/Rockstar: лаунчер и релей ничего не подменяют и не расшифровывают, трафик игрока сквозной; закон РФ:
  тексты нейтральные, слова «обход» нигде нет; слово «VPN» с 18.11 разрешено Александром и стоит только в карточке
  входа как совет «на время входа в FiveM» (docs/ПРАВИЛА.md).

Проверка без сборки: `?net=signin` (вход не отвечает, релей отвечает), `?net=signin&route=on` (маршрут включён),
`?net=signin&tunnel=0` (релей не отвечает). Тесты: `signin.rs` (чистка списка, блок hosts, строки), `tunnel.rs`
(отпечаток, разбор имени из хендшейка, пересылка через поддельный релей с закреплённым сертификатом, отказ при чужом
сертификате и чужом имени, проба статуса через два слоя TLS), `hosts.rs` (повышенная копия отвергает чужие строки).

## 7д. Отчёт для поддержки и подсказка после вылета (с версии 0.5.0)

**Отчёт.** Значок шестерёнки вверху → «Собрать отчёт для поддержки» (или ссылка «Отчёт для поддержки» под строкой о
вылете). Окно сначала показывает **список файлов** (имя и размер), и только по «Создать на рабочем столе» делает

игрок сам кидает файл в Discord, в канал поддержки. Код: `src-tauri/src/support.rs`, команды `support_preview`,
`support_create` в `lib.rs`.

В zip:

- последний `FiveM.app\logs\CitizenFX_log_*.log`;
- журнал игры последнего вылета за сутки (`FiveM.app\crashes\<номер>.dmp.gamelog`);

## 7е. Запасные адреса новостей и обновлений, подпись `news.json` (с версии 0.5.0)

**Зачем.** GitHub у части провайдеров РФ медленный или режется, а в `news.json` лежат адрес сервера, резервные
маршруты и релеи входа. Второй адрес на нашем сайте (в РФ его не режут) и подпись файла: подменённый список релеев
лаунчер не примет.

**Новости.** `launcher.config.json`: `newsUrl` (GitHub, первый) и `newsUrls` (`https://coldz.vip/launcher/news.json`).
Лаунчер спрашивает все адреса сразу и рядом с каждым `<адрес>.sig`; берёт первую копию с верной подписью, а если за
1,5 с после неё ответил другой адрес с более новым `signedAt`, то её (`lib.rs first_signed`). Без верной подписи файл не
используется: последняя хорошая копия из кэша (тоже только с подписью рядом) или вшитая в лаунчер. Проверка «есть ли
интернет» в проверке связи (раздел 7б) смотрит оба адреса.

**Ключ новостей — свой, не ключ обновлений.** minisign (как у обновлений), сделан 18.11.2026 `tauri signer generate`:
- секретный: `C:\Users\Aaenl\.coldz-launcher-keys\news.key` (без пароля; в git, чат и вывод не попадает; `*.key` в
  `.gitignore`). Вторую копию стоит хранить у Александра там же, где копию ключа обновлений. Потеря ключа новостей не
  страшна, как у обновлений: новая пара + новый выпуск лаунчера с новым `newsPubkey`;
- открытый: `launcher.config.json → newsPubkey` (и `news.key.pub` рядом с секретным). Тест `news_signature`
  проверяет, что он не совпадает с ключом обновлений и что `news/news.json.sig` подходит к `news/news.json`.

Подписать после каждой правки: `python scripts/sign-news.py` (пишет `signedAt`, сохраняет файл в обычном виде со
строками LF, делает `news/news.json.sig`, копирует оба файла в `release/site/launcher/`). В `.gitattributes`
`news/news.json -text`: git не меняет концы строк, GitHub отдаёт ровно подписанные байты.

**Обновления.** `tauri.conf.json → plugins.updater.endpoints`: сначала GitHub, потом
`https://coldz.vip/launcher/latest.json` (плагин обновлений идёт по списку, пока один не ответит). Сам `latest.json` и
установщик подписаны ключом обновлений, подмена на сайте не страшна. `npm run release` теперь кладёт в
`release\<версия>\site\launcher\` копию для сайта: установщик, `.sig`, `latest.json` со ссылкой на
`https://coldz.vip/launcher/COLDZ-Launcher_<версия>_x64-setup.exe`, и `news.json` + `.sig`.

**Выкладка на coldz.vip (делает главная, с резервной копией и проверкой, как обычный деплой сайта):**
1. Файлы `release/site/launcher/news.json` и `news.json.sig` (после каждой правки новостей), при выпуске ещё
   `release\<версия>\site\launcher\*` → в корень сайта, папка `/launcher/`. Старые установщики можно оставить.
2. Типы: `.json` → `application/json`, `.sig` → `text/plain`, `.exe` → `application/octet-stream`; кэш не дольше 5 минут
   (`Cache-Control: max-age=300`); только HTTPS.
3. Проверка: `curl -s https://coldz.vip/launcher/news.json | sha256sum` совпадает с `sha256sum news/news.json`;
   `curl -sI https://coldz.vip/launcher/news.json.sig` отвечает 200; при выпуске `latest.json` открывается и ссылка в
   нём качает установщик.
4. Пока на сайте файлов нет, лаунчер 0.5.0 работает с GitHub как раньше (адрес на сайте просто не ответит).

Проверка в тестах: `news_signature` (подпись, чужой ключ, испорченный байт), `news_from_the_first_good_address`
(мёртвый адрес и медленный, более новый `signedAt` выигрывает, неподписанный не берётся).

## 7ж. Перезапуск сервера, пинг маршрутов (с версии 0.5.0; линия онлайна за сутки убрана в 0.5.3)

**Сервер** (winter-server, ветка `feat/restart-var-1811`, `resources/[z]/z_menu/server/online.lua`, логика
`server/logic/online.lua`, числа `config.online`): раз в минуту запоминает, сколько игроков в сети (наибольшее за
5-минутку, сутки, переживает перезапуск: KVP ресурса). Время объявленного перезапуска берёт у z_admin
(`zrestart <мин>` или вкладка «Создатель» ставят `GlobalState.zRestartAt`). Отдаёт:
- `GET /z_menu/online` → `{ ok, now, step, max, restartAt, points: [[t, n], ...] }` (`now` и `restartAt` по часам
  сервера, поэтому неверные часы ПК не мешают; ответ собирается не чаще раза в 30 с, без лимита по IP: через резервные
  маршруты все лаунчеры приходят с адреса релея);
- `vars.coldz_restart_at` в `/info.json` (`SetConvarServerInfo`, unix, `0` — нет). Важно: в `/dynamic.json` у FXServer
  переменных нет, поэтому `/info.json`.

**Лаунчер** (`lib.rs server_info`, раз в минуту через выбранный маршрут): сначала `/z_menu/online`, у старого сервера
без него `vars.coldz_restart_at` из `/info.json` (тогда по часам ПК).
- Строка в ячейке статуса под «Подключение: …»: «Перезапуск через N мин» (за час и меньше), «Перезапуск меньше чем через
  минуту».
- «Играть» за 2 минуты до перезапуска и меньше: карточка «Перезапуск сервера» с кнопками «Всё равно играть» и
  «Закрыть» (FiveM не запускается без согласия). «Играть» по-прежнему не блокируется.
- Линия онлайна за сутки в ячейке «Игроки» была в 0.5.0-0.5.2; в 0.5.3 убрана по слову Александра (20.11): лаунчер
  берёт из `/z_menu/online` только `restartAt`, `points` сервер ещё отдаёт, но окно их не читает. Число «N / 48» осталось.
- «Проверить связь»: у сервера COLDZ пинг («отвечает · 34 мс»), каждый резервный маршрут своей строкой с пингом
  («Резервный маршрут 1 · 52 мс»). Пинг = время TCP-соединения, лучшее из 3, как в статусе. В `net-check.log` строка
  «пинг: основной … 34 мс, резерв №1 … нет ответа».

Предпросмотр: `?restart=12` (строка), `?restart=1&card=play` (карточка), `&card=check` (пинги).
Тесты: лаунчер `restart_and_online_from_the_server`, `tunnel_lines_name_the_relay_and_the_stop` (строка пинга);
сервер `tests/z_menu/launcher_online1811_spec.lua`.

## 7и. Портативная версия без установки (с версии 0.5.0)

Второй файл выпуска: `release\<версия>\COLDZ-Launcher_<версия>_x64-portable.zip` (делает `scripts/build.ps1` после
установщика, и в проверочной сборке тоже). Внутри `COLDZ Launcher.exe` и `portable.txt` (короткая памятка RU/EN и
строка лицензии FiveM).

- **Признак:** файл `portable.txt` рядом с exe (`lib.rs portable_dir`). Тогда `settings.json`, `net-check.log`,
  `fivem-search.log` и кэш новостей лежат рядом, в `data\` (у установленного: `%APPDATA%\com.coldz.launcher\`).
  Удалить `portable.txt` = обычный режим. Кэш самого окна (WebView2) остаётся в `%LOCALAPPDATA%\com.coldz.launcher\`:
  это делает WebView2, туда только язык и скрытая подсказка.
- **Обновления:** портативная сама не ставится (`install_update` → `portable`, фоновой загрузки нет). При новой
  версии строка «Это портативная версия: скачайте новую и распакуйте вместо этой.» и кнопка «Скачать» →
  `portableDownloadUrl` из `launcher.config.json` (сейчас `releases/latest` на GitHub; при закрытии репозитория
  поменять на страницу coldz.vip, раздел 7к).
- **Минусы** (поэтому только дополнительный файл): нет ярлыка и записи «Программы и компоненты», нет автообновления,
  WebView2 должен уже быть в Windows (в Windows 10/11 обычно есть; установщик ставит его сам, zip нет), exe без
  подписи Windows так же, как установщик.
- Загрузить zip в выпуск GitHub четвёртым файлом (и на coldz.vip в `/launcher/` по желанию).

Предпросмотр: `?portable=1&update=1`. Тест: `portable_marker`.

## 7к. Как закрыть репозиторий и не оставить игроков без обновлений (подготовка с версии 0.5.0)

**Что игроки берут с GitHub сейчас:** `news/news.json` (адрес сервера, резервные маршруты, релеи входа, новости),
`releases/latest/download/latest.json` и установщик (обновления), страница `releases/latest` (ссылка «скачать» на
сайте, в Discord и у портативной версии). Закрытый (private) репозиторий отдаёт на всё это 404.

**Зеркала (сделано в 0.5.0, раздел 7е):** `news.json` + `.sig`, `latest.json` и установщик лежат и на
`https://coldz.vip/launcher/`. Лаунчер 0.5.0+ спрашивает оба адреса, поэтому закрытие GitHub ему не мешает.

**Кому помешает:** лаунчерам 0.3.x и 0.4.0. Они знают только GitHub: после закрытия они не увидят новых новостей и
обновлений и останутся на последнем сохранённом `news.json` (адрес сервера и маршруты на момент закрытия). Если потом
поменяется адрес сервера или релеи, такие игроки не войдут, пока сами не скачают новый лаунчер.

**Порядок:**
1. Выпустить 0.5.0 (или новее) обычным порядком (раздел 5) и выложить зеркало на coldz.vip (раздел 7е, проверка
   `curl` там же). Ссылку «скачать лаунчер» на сайте и в Discord поменять на `https://coldz.vip/launcher/`
   (страница со ссылкой на установщик; её делает главная вместе с сайтом), `portableDownloadUrl` в
   `launcher.config.json` тоже.
2. Ждать, пока почти все обновятся. Лаунчер 0.3.x-0.4.0 предлагает обновление при каждом запуске, но ставит его только
   по кнопке «Обновить». Оценка: активные игроки (заходят раз в несколько дней) обновятся за 1-2 недели; через
   **3-4 недели** после выпуска 0.5.0 на старых версиях останутся в основном те, кто не заходит. Проверить точнее:
   лаунчер шлёт серверу `User-Agent: COLDZ-Launcher/<версия>` при нике (`POST /z_menu/nick`) и при `/z_menu/online`;
   можно попросить главную добавить в z_menu счёт «сколько разных лаунчеров каких версий за неделю» (сейчас не
   считается) и закрывать, когда старых меньше 5 %.
3. За неделю до закрытия: новость в `news.json` (4 языка) «Обновите лаунчер кнопкой «Обновить»: старая версия скоро
   перестанет получать новости» и то же в Discord. Старые лаунчеры её ещё увидят.
4. **Лучше не закрывать этот репозиторий, а разделить** (тогда старые лаунчеры не ломаются совсем): код перенести в
   новый закрытый репозиторий (например `coldz-launcher-src`), а в публичном `Poopseeque/coldz-launcher` оставить
   только `news/news.json`, `news/news.json.sig`, README из двух строк и выпуски (Releases). Старые 0.3.x-0.4.0 тогда
   продолжают читать новости и получать обновления, а исходников, адресов релеев в README и описания маршрута входа в
   открытом доступе больше нет. `news.json` в публичном репозитории и так содержит адреса релеев: это нужно лаунчеру,
   скрыть их нельзя ни так, ни так.
5. Если всё же закрывать целиком: сделать это не раньше срока из п. 2, после проверки, что `https://coldz.vip/launcher/`
   отдаёт свежие `news.json`, `latest.json` и установщик. После закрытия `scripts/verify-update.py --url` и
   `build.ps1` (берёт имя репозитория из первого адреса обновлений) продолжают работать по коду, но проверка `--url`
   смотрит GitHub: проверять зеркало `curl`ом.

До любого варианта: в истории git остаются старые файлы (адреса релеев, `relay/tunnel/README.md` до 0.4.0); при
разделении в публичный репозиторий переносится только `news/` без истории.

## 7л. Лаунчер «не запускается вообще»: WebView2 и ошибка при старте (ветка `fix/start-error-message`, после 0.5.1)

**Что было.** 20.11 стример: «ColdZ вообще не запускается, даже процесс не создаёт». Окно лаунчера рисует WebView2
(браузер Windows). Без него `tauri::Builder::build()` падает, release-сборка без консоли, и процесс исчезает за доли
секунды молча. Установщик проверяет только ключ реестра EdgeUpdate `pv`: если WebView2 удалили «чисткой» Windows, а
ключ остался, установщик WebView2 не ставит; портативный zip WebView2 не ставит никогда. Так же молча выходил 0.5.0.

**Что делает лаунчер** (`src-tauri/src/startup.rs`), до запуска Tauri:

1. `tauri::webview_version()`: нет WebView2 или он сломан — окно Windows на языке системы (RU, EN, ES, PT): «нужен
   компонент Microsoft Edge WebView2 Runtime», кнопка «Да» открывает страницу Microsoft
   `https://go.microsoft.com/fwlink/p/?LinkId=2124703`. Строка в `start-error.log`.
2. Любая паника пишется в `start-error.log` (папка настроек: `%APPDATA%\com.coldz.launcher\` или `data\` портативной).
   Паника в главном потоке (старт, `build()`) ещё и показывает окно с текстом ошибки и путём к журналу (Ctrl+C в окне
   копирует текст), чтобы игрок мог прислать его в группу.

**Проверка без поломки ПК:** `COLDZ_FAKE_NO_WEBVIEW2=1` (окно про WebView2), `COLDZ_FAKE_START_PANIC=1` (окно ошибки
старта). Тест `startup`: языки, тексты без длинных тире.

## 7м. Сборка игры до запуска FiveM (с версии 0.5.4)

**Что было.** 20.11 стример (5 дампов, `F:\COLDZ-work\crash_2011_sanych\разбор.md`): FiveM при входе на сервер с другой
сборкой игры пишет «FiveM needs to restart» и/или качает файлы игры **внутри уже запущенной игры** («Updating game
storage … 1423 MB»), а игра закрывается через ~96 с после старта: при медленном интернете вылет всегда. Если FiveM
запустить уже на нужной сборке, данные сборки он качает в своём окне запуска, до игры («FiveM needs to update the local
game data … download X GB» → Continue): там таймера нет (проверено у игрока).

**Как решает FiveM** (исходники citizenfx/fivem `5412ed86` от 11.11.2026): при каждом входе читает `vars` из
`http://<адрес>/info.json` сервера и сравнивает со своими:

| `vars` сервера (20.11) | что сравнивает FiveM | строка `[Game]` в `FiveM.app\CitizenFX.ini` | откуда FiveM берёт её при запуске |
|---|---|---|---|
| `sv_enforceGameBuild` `3258` (скоро 3889; 3717 → 3751) | сборка (данные игры) | `SavedBuildNumber=3258` | нет строки — своя сборка по умолчанию (сейчас 3258) |
| `sv_defaultGameBuild` `3889` | сборка exe | `DefaultBuild=3889` | нет строки — 3258: тогда «Switching from executable version 3258 to 3889» и перезапуск |
| `sv_pureLevel` `1` | pure-режим | `PureLevel=1` | 1 или 2 → `-pure_N`, иначе 0 |
| `sv_poolSizesIncrease` `{"InteriorProxy":450,"PortalInst":100}` | пулы (как JSON-объект) | `PoolSizesIncrease={"InteriorProxy":450,"PortalInst":100}` | пусто — без увеличения |

Отличается хоть одно — FiveM перезапускается в нужную сборку и пишет эти строки сам
(`NetLibrary.cpp`, `ConnectToNative.cpp RestartGameToOtherBuild`, `CrossBuildLaunch.cpp`, `XBRInit.cpp`,
`PoolSizesState.cpp`). `DefaultBuild` в задаче не было: добавлен, потому что без него свежий FiveM всё равно
перезапускается (у владельца в файле `DefaultBuild=3889`).

**Что делает лаунчер** (`src-tauri/src/gamebuild.rs`, `lib.rs game_build`, `sync_game_build`):

1. «Играть»: после выбора маршрута (раздел 7в), одновременно с ником, `GET http://<маршрут>/info.json` (не дольше 3 с),
   из `vars` — то, что выше (`gamebuild::wanted`). Нет ответа, нет `vars` или `sv_enforceGameBuild` — файл не трогаем.
2. Перед запуском FiveM, только если FiveM **не запущен** (раздел 7: `running::Decision::Launch`; запущенный FiveM сам
   перепишет файл при выходе): `FiveM.app\CitizenFX.ini` рядом с найденным FiveM.exe (раздел 7а) сравнивается так же, как
   сравнивает FiveM (имена без учёта регистра, первая секция `[Game]`, первая строка с ключом, пулы как JSON). Совпадает —
   файл не пишется. Нет строки `SavedBuildNumber`/`DefaultBuild` — пишется (умолчание FiveM может смениться).
3. Пишутся только отличающиеся строки: строка ключа заменяется на месте (её конец строки остаётся), новой строки нет —
   после последней непустой строки `[Game]`; нет `[Game]` — в конец. Все остальные строки, в том числе `IVPath` в
   кодировке Windows (кириллица в пути), остаются байт в байт; концы строк как в файле (CRLF, если файл новый); файл
   UTF-16 с BOM остаётся UTF-16. Запись через временный `CitizenFX.ini.coldz-tmp` и переименование.
4. Нет файла — создаётся с `[Game]` и четырьмя строками (FiveM потом сам спросит папку GTA, как при первом запуске).
   Нет папки `FiveM.app` — ничего не создаём. Файл «только для чтения», нет доступа — не трогаем (атрибут не снимаем).
5. Любая ошибка — строка в журнале, FiveM запускается как раньше. Журнал: `fivem-search.log` (он же в отчёте для
   поддержки, раздел 7д), запись ««Играть»: сборка игры для FiveM (CitizenFX.ini)»: что просит сервер, путь, «было →
   стало» по каждой строке или «совпадает с сервером, файл не тронут», «ошибка: не записать: файл только для чтения…».
   FiveM уже открыт — запись «FiveM запущен, CitizenFX.ini не трогаем».
6. Файл записан — под «Играть» строка (4 языка, `ui/i18n.js` `launched_build`): «FiveM запускается. Если FiveM
   предложит обновить данные игры, нажмите «Continue» и дождитесь конца загрузки: первый вход может занять несколько
   минут.» Окно сворачивается через 8 с (обычно 2,5 с), чтобы строку успели прочитать. Файл совпадал — как раньше.

**Не проверено и ограничения.**
- На настоящем FiveM с этим лаунчером не проверено (правило: на ПК владельца FiveM не запускаем, `CitizenFX.ini` не
  трогаем). Проверено: тесты на временных файлах и то, что FiveM 20.11 у игрока с `-b<сборка>` качал данные сборки в окне
  запуска.
- По разбору 20.11 (дампы 14:10 и 14:13) файл `update+update.rpf` сборки 3258 (1423 МБ) у свежей GTA (exe 3889)
  качался внутри игры даже при `FiveM.exe -b3258` и `-b3258 -pure_1`. Лаунчер убирает перезапуск и докачку при смене
  сборки, но эти 1423 МБ при сервере на 3258 может не убрать; на сборке сервера 3889 (= exe свежей GTA) их нет.
- Прямой запуск FiveM.exe с `-b` по-прежнему нельзя (раздел 7). Ссылка `fivem://connect/<адрес>?-b3258` FiveM читает
  (`CrossBuildLaunch.cpp`), но без pure, пулов и exe: поэтому файл.

Предпросмотр: `?build=1&card=play` (строка про «Continue»). Тесты: `gamebuild.rs` (разбор `vars`, exe как у FiveM,
плохие `vars`, файл владельца совпадает, другая сборка, байты `IVPath` в cp1251, CRLF/LF, без конца строки, другие
секции, пустой файл, pure и пулы как у FiveM, UTF-16, файл на диске: нет `FiveM.app`, создание, «не писать», только
для чтения), `lib.rs` `game_build_from_the_server` (поддельный сервер: 200, 404, не JSON, без сборки, никого нет),
`game_build_line_in_the_window` (4 языка, без длинных тире и запрещённых слов, `game_build` до `play`).
