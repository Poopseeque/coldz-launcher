# Туннель входа FiveM на релеях COLDZ (лаунчер 0.4.0, 18.11.2026)

Зачем: игроки из России не могут войти в FiveM без VPN, потому что домашние провайдеры режут вход Rockstar
(`scui.rockstargames.com`, `rgl-prod.ros.rockstargames.com`, `prod.ros.rockstargames.com`, `signin.rockstargames.com`,
`socialclub.rockstargames.com`; измерено 18.11, подробности `README.md` лаунчера, раздел 7г). Лаунчер по кнопке игрока
ведёт эти адреса через наш релей. На релее для этого нужен один порт и один файл конфигурации nginx, который там уже стоит.

## Как это работает на релее

1. Порт **8443**: TLS от лаунчера. Сертификат самоподписанный, лаунчер знает его по SHA-256 из `news.json`
   (`signin.tunnels[].sha256`). Чужой клиент без этого отпечатка ничего полезного не получит: внутри нужен TLS-хендшейк
   с именем из короткого списка.
2. Внутри этого TLS лаунчер передаёт соединение игрока как есть: это TLS-хендшейк самого FiveM с именем настоящего
   хоста. nginx читает имя без расшифровки (`ssl_preread`) и соединяется с настоящим хостом на 443, только для имён из
   списка (`*.rockstargames.com`, `rsg.sc`, `*.fivem.net`, `*.cfx.re`, `*.cfx-services.net`, `cfx-content.akamaized.net`).
   Остальное уходит на закрытый порт.
3. Шифрование между FiveM и Rockstar остаётся сквозным: релей видит только зашифрованные байты, ничего не подменяет.

Файлы: `tunnel.stream.conf` (вставляется `include` в блок `stream {}` файла `/etc/coldz/nginx/nginx.conf`),
`install_tunnel.sh` (ставит всё и печатает строку для `news.json`).

## Установка (на каждом релее, root)

```
scp -r relay/tunnel root@177.3.198.34:/root/tunnel      # Варшава (root по ключу aaro_ed25519)
ssh root@177.3.198.34 'sh /root/tunnel/install_tunnel.sh'
```

Алматы (46.247.40.34, пользователь `ubuntu`, `sudo`; там ufw активен, скрипт сам откроет 8443):

```
scp -r relay/tunnel ubuntu@46.247.40.34:/home/ubuntu/tunnel
ssh ubuntu@46.247.40.34 'sudo sh /home/ubuntu/tunnel/install_tunnel.sh'
```

Скрипт в конце печатает готовую строку вида
`{ "address": "177.3.198.34:8443", "sha256": "…64 hex…" }` — её вставить в `news/news.json` → `signin.tunnels`
(список, первый — Варшава) и запушить main. Новая версия лаунчера для этого не нужна, достаточно 0.4.0 у игрока.

Откат: убрать строку `include /etc/coldz/nginx/tunnel.stream.conf;` из `nginx.conf`, `systemctl reload coldz-relay-nginx`.
Бэкап `nginx.conf` до правки: `/var/backups/coldz-relay-<дата>-tunnel/`.

## Проверка после установки

- С ПК (из репозитория лаунчера): `cargo test --manifest-path src-tauri/Cargo.toml real_tunnel -- --ignored --nocapture`
  с адресом и отпечатком в переменных `COLDZ_TUNNEL=177.3.198.34:8443 COLDZ_TUNNEL_SHA256=…` — лаунчерный код
  открывает туннель и спрашивает `scui.rockstargames.com` через него (ждём любой HTTP-ответ, у Rockstar это 403).
- На релее: `ss -ltn | grep 8443`, журнал `/var/log/coldz-relay-nginx/stream.log` (строки `-> <ip>:443`).
- У игрока из России: лаунчер 0.4.0 → «Проверить связь» → строка «Вход в FiveM (Rockstar): нет связи» и «Резервный
  маршрут входа: работает» → кнопка «Включить резервный маршрут входа» → запрос Windows → «Играть».

## Что учесть

- Трафик входа маленький (страница входа и запросы лицензии, сотни КБ), игровой трафик через туннель не идёт.
- Релей видит IP игроков, подключающихся к Rockstar через него; журнал stream.log хранит адреса, ротация как у
  остального релея. Rockstar видит IP релея, не игрока.
- Имена в списке `map` расширять только осознанно: это не общий прокси.
- Защита от перебора не ставилась: при злоупотреблении добавить `limit_conn` на 8443.
